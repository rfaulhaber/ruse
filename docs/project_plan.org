#+TITLE: Ruse Implementation Plan
#+AUTHOR: Ryan Faulhaber
#+STARTUP: overview logdone

Working plan for taking *ruse* from its current frontend-only state to a conforming
R7RS Scheme on the RBC-1 register bytecode VM.

*The goal of this leg is a bytecode interpreter.* Milestones M0–M9 are the project.
A JIT is an eventual ambition, sketched in [[*Beyond the interpreter: the eventual JIT][Beyond the interpreter]] so that a few cheap
decisions don't foreclose it — but nothing in M0–M9 is shaped around it, and no JIT work
is scheduled.

This supersedes [[file:ROADMAP.md][ROADMAP.md]], which it carries forward largely intact. What is new here is
the corrected status assessment, the org task structure, and the deferred-JIT section.

No dates. This is a solo side project with a 10-month gap in its commit history;
invented deadlines would only go stale. Effort is relative (S/M/L/XL); the ordering
constraints are what actually matter.

** What does not exist

The reader and the runtime foundation exist but nothing joins them: no instruction
encoding, no VM, no compiler, no numeric tower beyond the fixnum/bignum boundary, no macro
expander, no standard library, no ports, no conformance driver. The reader plus M1 is
roughly 10% of the work by volume and rather less than that by difficulty.

* Frozen decisions A–H

Ratified previously and unchanged. See [[file:ROADMAP.md][ROADMAP.md]] for the full rationale table.

| # | Decision |
|---|----------|
| A | ~Value~ is ~repr(transparent) struct Value(u64)~, NaN-boxed: immediate flonums, 48-bit fixnums, chars, 6 singletons, one heap-pointer tag. Hardware NaNs canonicalized to a fixed non-signature pattern |
| B | GC is precise, non-moving, stop-the-world tri-color mark-sweep, ~Drop~-on-sweep. Write barriers emitted as no-ops from day one |
| C | Compiler is direct syntax-directed codegen (destination-register + tail-flag descent) over a typed Core IR, with a Lua-5 ~FuncState~ register allocator. No CPS, no ANF |
| D | Numeric tower on ~num-bigint~/~num-rational~/~num-integer~/~num-traits~. 48-bit fixnum with centralized promote/demote |
| E | Hygiene via Flatt scope-sets; a ~Syntax~ type designed *before* the expander. An unhygienic gensym-rename prototype lands first |
| F | One ~Continuation~ heap object, callable. Escape-only capture first, then upgraded in place to multi-shot via whole-stack copy |
| G | Stdlib in 3 layers: opcode-backed prims, a ~PRIMCALL~ native-fn table, and a baked-in =prelude.scm=. Every prim is *also* a global-slot procedure |
| H | ~read~ produces a runtime ~Value~ datum graph (cyclic-capable), not the tree ~Expr~ |

Also frozen: 50 real opcodes with =0x40=–=0x45= reserved for RBC-2; strict R7RS semantics
(exact-rational ~DIV~, non-transferring ~with-exception-handler~, IEEE ~(/ 1.0 0.0)~ ⇒
~+inf.0~); tests key on *disassembly text, never raw bytes*.

* Four habits that cost nothing and keep the door open

Each of these is justified on its own merits for the interpreter. That they also happen
to make a future JIT tractable is a bonus, not the reason — none of them is a tax on
M0–M9. They are called out here only because the *opposite* choice in each case is the
natural one to drift into, and all four are expensive to reverse later.

1. *Tag constants and heap layout live in one module.* ~repr(C)~ on every heap type,
   with the NaN-box masks and shifts defined once in =src/value/layout.rs=. Justified
   now because tag logic duplicated across the allocator, the GC, and the printer will
   diverge; ~const~ offset assertions catch layout drift at compile time.

2. *Opcode semantics live in standalone runtime functions, not in ~match~ arms.* Each
   dispatch arm decodes operands and calls e.g. ~rt::add(a, b) -> Result<Value, VmError>~.
   Justified now because it makes every opcode unit-testable without booting a VM, keeps
   the dispatch loop small enough to read, and stops the numeric tower's entry points from
   being buried inside a 2000-line ~match~. *This is the one most easily lost* — the
   natural way to write a bytecode interpreter is semantics inline in the arms.

3. *Global access is one indirection through a stable-address, append-only slot vector.*
   Not optional: R7RS §5.4 requires redefinition to take retroactive effect, so
   ~GETGLOBAL~ can never inline a direct address. The slot key must be decoupled from the
   constant-pool name string used for diagnostics.

4. *The interpreter stays the authority on behavior.* Anything that answers "what does
   this program do" — the numeric tower, ~equal?~, the printer — belongs behind an
   interface rather than inside the evaluator, so a second consumer never needs a second
   implementation. Cheap discipline now; the difference between one Scheme and two later.

** What the encoding settled on

Boxed values hide in the *negative* quiet-NaN region: sign, exponent and quiet bit all set,
then a 3-bit tag at bits 50–48 and a 48-bit payload. Tags used: singleton, char, fixnum,
heap pointer; four spare. Every NaN is canonicalized on the way in to a *positive* quiet NaN,
which is not optional — x86-64 returns ~0xFFF8000000000000~ from ~0.0 / 0.0~, and that is
exactly the signature word with tag 0.

Singleton ordinal 0 is therefore ~undefined~, not ~#f~ and not a null pointer: if an
uncanonicalized NaN ever does leak in, the black-hole marker errors loudly downstream rather
than answering a silently wrong ~#f~ or dereferencing null. ~#f~=4 and ~#t~=5 make
~is_boolean~ one mask and one compare, and truthiness one compare against ~#f~.

** Two decisions worth knowing before M2 and M3

- *Allocation never collects.* A precise collector frees exactly what no root reports, so a
  collection inside ~cons~ would reap every temporary the caller is holding in a Rust local.
  ~Heap::should_collect~ reports when a collection is due and the VM picks the safepoint —
  an instruction boundary, where the register file is a complete root set. Native code that
  allocates twice in a row pins across the gap (=src/gc/handle.rs=).
- *Heap objects are reached through ~Heap::get~/~get_mut~, never through a raw ~Value~.* The
  borrow of the heap is what makes the dereference safe, and it is also what stops a
  reference into the heap being held across an allocation.

** What the adversarial review of the implementation found

Four independent review lenses over the finished code, each finding then handed to a skeptic
tasked with refuting it: ten findings raised, six survived, deduplicating to three real
defects. All three were reproduced from an external crate containing no ~unsafe~, and all
three are fixed.

1. *Blocker — safe outside code could retag a live object.* ~GcHeader::tag~ was ~pub~ and
   ~HeapObject::header_mut~ was a safe method on a public trait, so
   ~heap.get_mut::&lt;Pair&gt;(p).unwrap().header_mut().tag = HeapTag::Str~ compiled — and the
   sweep then reconstructed a ~Box&lt;Str&gt;~ from a ~Pair~ allocation. A collector's tag byte is
   as privileged as a vtable pointer. Header access moved to a crate-private supertrait,
   which also seals ~HeapObject~ — necessary because ~Heap::get::&lt;T&gt;~ is generic over it, so
   a foreign ~unsafe impl~ claiming ~TAG = Pair~ would hand out its own type over a pair's
   memory. Both holes are now locked shut by ~compile_fail~ doctests.

2. *Major — the pin shadow stack lost pins under nesting.* Scopes recorded a base index and
   truncated to it, so a pin taken from an *enclosing* scope while an inner scope was open
   sat above the inner scope's mark and was silently released when it closed — precisely the
   accumulator-plus-temporaries idiom nesting exists for. Rewritten so a pin is a stable
   slot, not a position: each scope releases only the slots it allocated, released slots bump
   a generation so a stale handle is caught rather than aliasing, drop order no longer
   matters, and a forgotten scope over-roots (safe) instead of under-rooting.

3. *Major — the accessors' documented obligation was the wrong one.* ~Heap::get~ claimed the
   heap borrow was proof of safety. It is not: it gives the returned *reference* a correct
   lifetime, but a ~Value~ is ~Copy~ with no lifetime, so one captured before a collection
   that did not reach it is dangling — and the quiet failure is worse than the crash, since
   a later allocation reuses the block and the stale ~Value~ starts naming a different live
   object. The docs now state the real obligation, and a ~#[cfg(debug_assertions)]~ registry
   of owned addresses turns a stale or cross-heap ~Value~ into a loud failure in tests and
   under Miri, at zero release cost. The permanent answer is the open question above.

** Deferred out of M1, deliberately

- The ~Closure~ heap object needs ~Proto~, which is an M2 artifact. The *tag* is declared now
  so the numbering never moves; nothing can allocate one, and the three tag dispatches
  (trace, drop, size) carry a ~debug_assert!~ arm that M2 replaces.
- Decision A's ~cfg~-gated tagged-enum fallback for debugging and LA57 platforms is not
  built. In its place ~Value::from_header_ptr~ asserts that every allocation fits in 48 bits,
  so an unsupported platform fails loudly at the first ~cons~ instead of truncating pointers.
- ~Str~ stores UTF-8, which makes ~string-ref~ O(n). Same trade chibi makes; revisit in M9 if
  conformance work shows it hurting.

* Beyond the interpreter: the eventual JIT

Not scheduled, not decided, and explicitly not the current goal. Recorded so the thinking
isn't lost and so the shape is known when the time comes. Nothing in M0–M9 depends on any
of it; the [[*Four habits that cost nothing and keep the door open][four habits]] above are the entire hedge, and each stands on its own merits.

Treat everything below as a sketch to be argued with later, not a plan.

** Likely shape

Three tiers, with the interpreter as permanent ground truth and deopt target:

- *Tier 0* — the RBC-1 interpreter. Never removed, never modified to accommodate a
  compiler. Every JIT bug is found by disagreement with it, which only works if it stays
  independent.
- *Tier 1* — a baseline JIT: per-~Proto~ straight-line lowering of each bytecode, no
  speculation, no inlining, calling the same =src/rt/= functions the interpreter calls.
  Buys back dispatch and operand-decode overhead.
- *Tier 2* — speculative optimization driven by type feedback: unboxed fixnums and
  flonums in machine registers, guards, deopt to Tier 0 at a bytecode PC, inlining of
  small callees and ~PRIMCALL~ s.

** The constraint that will dominate the design

Decisions B (precise, non-moving GC) and F (~call/cc~ by whole-stack copy) together
rule out the conventional shape, where a method JIT keeps Scheme values in machine
registers and uses the native call stack. That shape would need GC stack maps for
precise root discovery, and would leave ~call/cc~ with no copyable frame stack.

The workable answer is that generated code operates on the *interpreter's* data
structures — the fiber's ~Vec<Value>~ register window and the same ~Frame~ records — and
spills every live value to memory at each safepoint. It costs spill traffic and buys back
correctness on the two hardest features in the language. Worth revisiting only with
evidence, not with intuition.

** Open, when the time comes

- Backend. Cranelift is the obvious first candidate: pure Rust so the Nix closure stays
  clean (the reasoning that chose ~num-bigint~ over GMP), targets x86-64 and aarch64,
  built for JIT use. Copy-and-patch stencils would compile faster but need build-time
  stencil extraction; LLVM is too heavy for a baseline tier; ~dynasm-rs~ means
  hand-writing encodings for two architectures.
- Whether Tier 1 compiles whole ~Proto~ s or only reached regions.
- Whether compilation happens off-thread, and how that interacts with GC.
- Code-memory lifetime: are compiled entries GC roots for their ~Proto~ (simple, leaks)
  or collected with it (correct, more plumbing)?
- Re-entering a captured continuation whose frames were originally JIT-compiled, when
  the compiled entry has since been invalidated.
- A differential harness running the corpus under both tiers with byte-identical output
  required — the enforcement mechanism for "the JIT changes speed, never behavior."

** Also deferred, and unrelated to the JIT

The reserved opcodes =0x40=–=0x45= are for the RBC-2 concurrency set (~SPAWN~, ~YIELD~,
~RESUME~, ~CHANMAKE~, ~CHANSEND~, ~CHANRECV~), which needs a fiber scheduler and
postdates a working sequential VM. The spec's deferred flonum-specialized opcode tier
(§1.2) belongs in the same bucket: revisit with profiles, not before.

* Open questions to pin before the relevant code freezes

- [ ] *~CADR~ C-byte bit layout* (spec open-Q 1) and the *~TYPEP~ type-selector enum*
      (open-Q 2) — freeze jointly between VM and compiler. Until then emit plain
      ~CAR~/~CDR~ chains and EQV chains for ~case~
- [ ] *Global slot namespace across libraries* (open-Q 3): one append-only slot vector
      with import-as-aliasing, versus per-library namespaces. Constrains ~GETGLOBAL~
      resolution and REPL retroactive redefinition (§5.4)
- [ ] *~PRIMCALL~ conventions* beyond 256 entries (the globals-as-procedures fallback),
      and the variadic and multiple-value calling conventions the spec leaves unspecified
- [ ] *Non-R7RS extensions*: keep ~[ ]~ bracket lists and the ~#!eof~/~#!default~
      singletons, or drop them? Commit to exact complex (R7RS permits omitting it, but
      the suite tests it)?
- [ ] *~DIV~ policy* (spec open-Q 4): confirm the "divides evenly" fast path earns its
      branch, or whether ~DIV~ should always go to the runtime with ~QUOT~ carrying the
      fast integer path alone
- [ ] *Line-info table format* (spec open-Q 5) — needed by ~error~ source locations
      before the compiler is pleasant to debug
- [ ] *The safe-versus-unsafe heap-access contract* — decide before M3 writes its inner
      loop. ~Heap::get~/~get_mut~/~tag_of~ are safe functions whose real precondition is
      that the ~Value~ has not been swept; a ~Value~ is ~Copy~ and carries no lifetime, so
      nothing enforces it. M1 ships a ~debug_assert!~ against a registry of owned addresses,
      which catches it in tests and under Miri but not in release. The two candidate
      resolutions: mark the *accessors* ~unsafe fn~ (coherent, but puts ~unsafe~ on every
      field read in the dispatch loop, which desensitizes), or mark the *invalidating*
      operation unsafe — ~pub unsafe fn collect~, contract "every ~Value~ live after this
      returns must be reachable from ~roots~ or the pin stack" — which is the ~Vec::set_len~
      shape and costs one ~unsafe~ block per safepoint, exactly where the root set genuinely
      has to be complete. The second looks stronger. Branding ~Value~ with the heap's
      lifetime does *not* resolve it: a branded ~Value~ is still stale after a collection of
      its own heap, and the sound version is ~gc-arena~'s ~Gc<'gc, T>~, which is a redesign
      of the ~Copy~ NaN-boxed word
- [ ] *~LOADIMM~ operand mapping* — =ruse-bytecode-spec.md= §4.1 lists the immediate
      singletons as ~0=#f 1=#t 2='() 3=unspecified 4=eof 5=undefined~; =src/value/layout.rs=
      assigns the opposite. No code is affected yet. ~SINGLETON_UNDEFINED~ must stay 0 —
      that is pinned by the x86-64 indefinite-QNaN assertion, not by the boolean-adjacency
      ones, which hold under either ordering. When the ~Op~ enum lands, define ~LOADIMM~'s
      operand *as* the =layout.rs= ordinal and amend the spec to point at it, the same
      treatment already applied to the spec's "56 opcodes" prose. Do not add a second table
- [ ] *Weak symbol interner*, before ~string->symbol~ lands (M6). Interned symbols are
      permanent roots today, so unbounded distinct names retain forever and lengthen every
      mark. Landing a weak interner now would be actively harmful — it makes ~Heap::symbol~'s
      result collectable while nothing in the tree traces symbols. Precondition for the
      change: constant pools, the global environment and the reader's in-flight values are
      all traced, and ~Heap::symbol~ callers pin across allocations. Then drop ~symbols~ from
      the root walk and evict in ~sweep~ (white + tag ~Symbol~ + ~interned~ ⇒ remove the key,
      which shares its ~Rc<str>~ with the symbol)

* Sequencing notes

The critical path is *M0 → M1 → M2 → M3 → M7 → M9*. Everything else either hangs off M3
or feeds M9.

- *M3 is the milestone that matters.* It is the first end-to-end result, and it fixes the
  shape that M4–M9 are all written against. Time spent getting the dispatch loop, the
  runtime-function split, and the ~FuncState~ allocator right is repaid several times.
- *M7 is the risk.* First-class control cannot be retrofitted; if something in the frame
  or upvalue design is going to be wrong, this is where it surfaces. Prefer discovering
  that before M8 and M9 pile on top.
- *M4, M5, M6 and M8 are parallelizable* once M3 lands, and are largely independent of
  each other. They are where to go when the runtime work needs a break.
- *Wire =r7rs.scm= slices in as early as they will run.* The incremental, error-tolerant
  driver from M3 turns a 2518-line all-or-nothing file into a score that goes up, which
  is the difference between a conformance suite that motivates and one that sits unused.
